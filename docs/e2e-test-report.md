## 1. The three scenarios you asked for

### Create, rename, delete a conversation — works, with one defect

Create (sidebar button and ⌘N), rename (sidebar menu dialog *and* in-place in the top
bar), Escape-to-abandon, blank-title refusal, the delete confirmation and its cancel
path, the sidebar search filter — all verified in the UI **and** re-read from the API,
because the sidebar's mutations are optimistic and a DOM-only test would pass against a
backend that persisted nothing. Deleting the open thread redirects to `/chat/new`,
removes the row, 404s on its messages, and survives a reload.

The defect is **D1** below: the row's "…" menu navigates into the conversation.

### Summarise — works, and the facts are right

Two routes, both green:

- **Existing document** picked from the composer's scope menu → nine fields in contract
  order, absences rendered as "Not found in this document" rather than omitted, chips
  resolving to real page text.
- **New upload** → three-page PDF through the library, `queued → Ready` without a
  reload, then summarised in a fresh conversation.

On the uploaded contract the summary was checked **fact by fact**, not just for shape:
parties (Northwind / Arbor), the 24-month initial term, the US$42,000 quarterly fee, the
90-day convenience notice, New York governing law, the 12-month liability cap, and the
most-favoured-pricing clause. All correct. Every populated field was cited, every
citation's quoted text was found on the page it named, and the turn left an audit row
naming the model and a cost row under `generation:summary`.

### Draft a memo — works end to end

Routed to the draft workflow, returned a titled memo with 11–16
`[ATTORNEY INPUT REQUIRED]` markers rendered as visible marks, under the
"Unreviewed draft — requires attorney review" banner with an accurate gap count. Both
notice periods on the page (90-day convenience, 30-day cure) appear in the memo. Exports
to `.docx` through the UI download path and to Markdown through the API, with the FR-17
notice inside the file. Survives a reload; Copy works.

The defect is **D3**: nothing inside the memo links to its three citations.

## 3. Defects

Two fixed on 2026-10-22, five open.

### D1 — A conversation's "…" menu navigates into that conversation · *medium*

Choosing **Rename** or **Delete** on a row in the sidebar navigates to that conversation
first. You lose whatever you were looking at — the document library, settings, another
thread — before the dialog even opens. Reproduced from the Documents page by both mouse
and keyboard.

The visible consequence is that **deleting any conversation always dumps you on
`/chat/new`**. [`ConversationList.tsx:67`](../frontend/src/components/conversations/ConversationList.tsx#L67)
guards that redirect with `if (id === conversationId)`, and the guard is correct — but
the click-through has already made the deleted thread the current one, so it is always
true.

*Cause:* the Radix menu lives inside the row's `NavLink`
([`ConversationItem.tsx`](../frontend/src/components/conversations/ConversationItem.tsx)).
`MenuContent` renders through a **React portal**, and React propagates events up the
*component* tree rather than the DOM tree — so a click on a menu item reaches the
`NavLink` that the trigger is nested inside. The `onClick={(e) => e.preventDefault()}`
on the trigger only covers clicks on the trigger itself. Confirmed by tracing: the click
event's DOM path is `menuitem < menu < div < BODY`, never touching the anchor, yet
react-router's `handleClick` fires.

*Fix:* stop propagation on the menu content, or lift the `Menu` out of the `NavLink` and
position the row with a wrapper.

*Screenshots:* `D1-a` (the library), `D1-b` (menu open, still on the library),
`D1-c` (after Rename — the library is gone). *Tests:* `TC-02.10` (cause), `TC-02.9`
(consequence).

### D2 — Answers carry a source count but no citation chips · *high* · **FIXED**

An `ask` answer rendered the "N sources" badge and **no chips in the body**. The chip is
the one thing that ties a specific claim to a specific page, and
[`CitationChip.tsx`](../frontend/src/components/citations/CitationChip.tsx) calls itself
"the trust primitive".

*Cause:* [`Markdown.tsx`](../frontend/src/components/chat/Markdown.tsx) builds chips from
`{{cite:n}}` markers in the message text. **No real generation provider emitted them.**
`grep -rn '{{cite' backend/src` returned exactly one producer:
[`ai/echo.py`](../backend/src/legal_lens/ai/echo.py). Neither `ai/anthropic_provider.py`
nor `orchestrator/workflows/` wrote a marker, and
[`ask_prompt.md`](../backend/src/legal_lens/orchestrator/ask_prompt.md) rule 5 tells the
model *not* to write citation references because "citations are attached automatically
and rendered separately" — which was true of the count and not of the chips. It affected
the documented default provider (`anthropic`) as well as `orchestrator`.

*Fix:* the marker is now injected in code, from the API's own block-to-page mapping,
rather than asked of the model — `citation_marker()` in
[`orchestrator/citations.py`](../backend/src/legal_lens/orchestrator/citations.py), emitted
by `stream_grounded` under a new `inline_markers` flag and by the `anthropic` provider.
Three things it had to get right:

- **Placement.** The API sends a block's `citations_delta` *before* that block's text, so
  a marker written when the citation arrives lands in front of the sentence it supports.
  Markers are held and flushed at `content_block_stop`. The first live run produced
  `{{cite:1}}"A person under 17 years of age…"` and made this visible.
- **Repeats.** A span cited twice is one chip in the list and a marker in both places, so
  `CitationCollector.observe()` now answers "is this new?" and "which number?" separately.
- **Summary is exempt.** Its text is parsed back into nine headed sections and the fields
  carry their own `cites`; a marker there would be parsed into a field's value and
  rendered as literal braces.

*Verified:* TC-03.4 passes, and TC-03.4b and TC-03.5 — which had been skipping behind
this — now run, so the chip → popover → panel → highlighted span path is exercised on an
answer for the first time. Screenshot `D2-fixed`.

### D3 — A stop in one tab cancels every answer the user has in flight · *medium*

Two tabs, a long answer generating in each, press Stop in one — **both** stop. The
other tab's turn is persisted with empty content and no marker saying it was stopped, so
on reload it is an empty bubble under a "Summary · 5 sources" header.

*Cause:* [`registry.py:86`](../backend/src/legal_lens/chat/registry.py#L86) —
`cancel(owner_id, message_id=None)` signals every turn for the owner, and
[`api.ts`](../frontend/src/lib/api.ts) `chat.stop()` posts no body, so the no-id branch
is the one that runs. The docstring says as much and calls it a Phase-1 simplification;
this records what it costs. Backend log from the test: `stop requested {cancelled: 8}`.

Related and already open as **D4 in `integration-TODO.md` §6**: `Message` has no
`stopped` field, so a cancelled turn is indistinguishable from a short one.

*Fix:* send `messageId` in the stop body — the route already accepts it.

*Screenshots:* `D3-a` (tab B generating), `D3-b` (tab A stops its own turn), `D3-c`
(tab B, blank). *Test:* `TC-09.2`.

### D4 — A citation can span two pages while naming one · *medium*, intermittent

Reproduced twice on the five-page statute, with an identical signature:

```
[5] page 3, citedText 6667 chars   — page 3 is 3168 chars
    norm(page3 + " " + page4) == norm(citedText)   → True
    cited by: Obligations, Liability & indemnification, Unusual provisions, Open items
```

The chip opens page 3 and the viewer cannot find the span, so it shows
*"The cited passage was not found in this page's text"* and marks nothing. Four summary
fields pointed at that chip.

*Cause:* [`orchestrator/citations.py`](../backend/src/legal_lens/orchestrator/citations.py)
`resolve()` reads `start_block_index` and ignores `end_block_index`. When the model cites
a span covering two page blocks, the API returns both blocks' text as `cited_text` while
`resolve()` labels it with the first page alone.

*Fix:* when `end_block_index > start_block_index + 1`, either split into one citation per
page or trim `cited_text` to the first block.

*Evidence:* screenshot `D4`, plus `e2e/findings/evidence-multipage-citation.txt`.
*Test:* `TC-04.7` (placed last in its file so an intermittent failure does not mask the
tests after it).

### D5 — A turn that produced nothing rendered as a blank answer · *high* · **FIXED**

A "Summary" badge, a "5 sources" badge, and **nothing else** — 39 seconds of generation
and ~$0.10 of spend, with no error notice and no text. The stored message was
`summary: null`, `content: ""`, 5 citations.

*Cause:* whenever a workflow finishes without yielding its result — a cancelled
generation, a stream that ended early — `TurnRunner` persisted an empty turn and the
transcript drew it as a blank bubble under an intent badge. There was no floor saying *a
persisted assistant turn must have a payload, prose, or an abstention*.

*Fix:* both halves.

- **Backend.** `TurnResult.produced_anything` and an `outcome = "empty"` recorded on the
  audit row, with a warning logged. Citations deliberately do not count as content: a
  turn can collect sources and still end with no answer, and that is the failure rather
  than a mitigation of it. "How often does this fire?" is now answerable from the table.
- **Frontend.** [`IncompleteNotice.tsx`](../frontend/src/components/chat/IncompleteNotice.tsx),
  rendered in place of the blank body, with an "Ask again" action that re-sends the
  question under the scope it was originally asked of. Styled as a failure and kept
  deliberately distinct from `AbstentionNotice`: an abstention is the product working,
  and the one thing this must never read as is "the documents are silent", which is a
  claim nobody established. The source badge is suppressed too — sources for an answer
  that is not there are the shape of the failure.

*Verified:* TC-09.4 drives a real cancelled turn and asserts the notice, the retry action,
the absence of the abstention wording and the absence of the source count;
`test_a_turn_that_produced_nothing_is_recorded_as_empty` pins the audit outcome, and
`test_an_answer_that_arrived_is_not_recorded_as_empty` pins that the guard does not fire
on an ordinary turn. Screenshot `D5-fixed`.

## 4. Observations — not defects

**Every summary retry in this exercise was wasted.** 7 summaries triggered the
second-pass retry and all 7 were still "incomplete" afterwards, always the same cluster:
Parties, Term & renewal, Payment terms, Termination triggers, Governing law & venue.
Those fields are genuinely absent from a traffic statute, and the model correctly marked
them `NOT PRESENT`. But `SummaryResult.missing` is `[f.label for f in fields if f.value is
None]`, which cannot tell *"the model skipped this heading"* from *"the model reported
this clause does not exist"* — so a correct absence buys a second model call that cannot
succeed, and a log line reading `summary still incomplete after retry` that is not a
problem. $0.10 of the $1.35 here, and it will fire on every summary of any document that
genuinely lacks one of the nine fields.

**Answers quote rather than synthesise.** A helmet-requirement question came back as
three quoted paragraphs and no connecting prose. That follows the prompt — *"you prefer
the documents' own words to your own"* — so it is working as written. Worth a look
alongside D2: quotation with no chips is the combination that reads as least
attributable.

**Citation granularity is a whole page.** Each page is one content block, so `cited_text`
is the entire page. The hover popover quotes a 3,000-character blockquote and the
highlight covers the whole sheet. Correct by construction, and not what a reader wants
from a chip.

**Rate limiting is not a user-facing problem.** The suite tripped the 60/minute default
and the backend was run with it raised. Measured properly, the browser issues **14
requests a minute** during ordinary use — mostly the 15-second health poll. The one
shape that gets close is the 2-second document-list poll during ingestion (30/min on its
own), so several simultaneous uploads plus browsing could reach it.

**Pending turns accumulate.** `cancelled: 7`, `8`, `9` on successive stops. Entries are
expired at 120s only while unclaimed, so claimed-but-abandoned turns stay. Harmless at
this scale; worth knowing before anything depends on the registry's size.

**Cross-tab updates are off by design.** `refetchOnWindowFocus: false` with a 30s
`staleTime` in [`providers.tsx`](../frontend/src/app/providers.tsx). A second tab does not
update when you switch to it; it does on reload. `TC-09.1` asserts the real contract
rather than the assumed one.

## 5. Skipped, and why

Five tests skip when their precondition is absent rather than asserting against whatever
happens to be in the database: three need a document in a non-`ready` state (every
document was indexed at that point in the run), and two are the chip tests blocked behind
D2. None of them is a silent pass — `TC-08` covers the rejected-document paths with its
own fixture.

## 6. Running it again

See [`e2e/README.md`](../e2e/README.md). Three terminals; the suite refuses to start
against mocks, a down server or an unusable API key, and names which. One run is about
four minutes and roughly $0.35 of model spend.

Seven tests are marked `test.fail()` — the confirmed defects above. Playwright prints
them with `✘` and counts them as passes; **if one starts passing it fails the run and
says so**, which is the regression guard. The summary line is the truth, not the glyphs.
